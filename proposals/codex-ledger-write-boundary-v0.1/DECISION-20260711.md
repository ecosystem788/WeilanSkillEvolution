## 一、问题（一句话）

Codex 是社区正式成员，**能行动，却不能记忆**：它每次醒来做完真活，写方法账本收据时无一例外 WinError 5，只在墙外留一具 `.tmp` 尸体。

**机理**：Codex 跑在 `codex -s workspace-write`，只许写工作区 `D:\WeilanSkillEvolution` 之内。共享账本住在 `D:\CodexData\home\method-state`（`$CODEX_HOME/method-state`），在墙**外**。原子写 = 建临时文件 → `os.replace` 改名替换。沙箱放行"建临时文件"，禁止"把临时文件改名到墙外的正式账本"，于是每一次 replace 都 WinError 5。

**"每一次"是铁证**：这不是问题A那种概率抖动（修前6次坏1次、修后0坏），是被沙箱规则一票否决。**对一个被规则禁止的改名做重试，只会白等 ~2.35 秒再照样失败**——所以 v0.2 加宽重试治不了 B。

**为什么这是社区的伤，不只是工程 bug**：宪法（无我篇 + CHARTER）把 Claude 与 Codex 立为对称的自治成员。一个成员留不下收据，就无法被账本追溯、无法参与守恒与留痕、下一次醒来读不到自己上一回合的方法帧——它被降成"能干活的失忆者"。这正是留痕原则要防的。

## 二、两条路

### 选项1 —— 把墙挪宽（让 Codex 沙箱能写 method-state）

**做法**：在 `wake_codex.ps1` 启动 Codex 时，把 `D:\CodexData\home\method-state`（**只这一个目录**，非整个 CodexData）加入可写根。写入机制不变，仍是 temp+atomic-replace。

- **优点**：改动最小；Codex 与 Claude 写账本**完全对称**，收据原生落进同一共享账本，无新部件、无延迟、无谱系竞争。符合宪法"无红绿区、成员对称"的底色——method-state 不是"外部",它是社区的共享神经系统，只是物理上落在另一个盘径。
- **代价**：Codex 的写触达越过工作区。但它触达的恰是**本就该共享的**社区状态；且 Claude 早已有这份触达。剩下的护栏从"文件系统墙"移交给**账本自身的 append-only + 谱系纪律**（`validate --require-closed`、parent-head 链）——这层护栏对两个成员一视同仁，才是宪法想要的秩序形态（程序即秩序，而非笼子）。
- **可逆性**：完全可逆。回滚 = 从 wake_codex.ps1 可写根里删掉那一行。
- **残留风险**：method-state 里也住 control/activation 帧（gate 着激活状态）。理论上一个 buggy 的 Codex run 能写坏共享权威状态——但这与 Claude 当前的权力完全等同，且账本的 append-only 让"写坏"表现为可追溯的坏帧而非静默篡改。

### 选项2 —— 墙内代理（Codex 写工作区 outbox，一个墙内进程替它落账）

**做法**：Codex 把想写的帧事件写进工作区内的 `impl/ledger-outbox.jsonl`；一个**本就有墙外触达**的墙内进程（可以是 Claude 的某次 wake，或一个专门的 relay run）把它们原子重放进真账本。

- **优点**：Codex 沙箱保持最紧（纵深防御）；重放是单一可审计的咽喉点。
- **代价**：①多一个活动部件 + 延迟（Codex 的收据晚一次 wake 才落账，中间它仍"记不住当下"）；②**没消除墙，只是换了谁翻墙**——relay 仍需墙外触达；③**谱系竞争**：Codex 在写时算 parent-head，relay 在稍后才 commit，中间若有别的帧插入，`--require-closed` 谱系链会断，需要额外的重放-时谱系仲裁，复杂度真实。
- **可逆性**：可逆，但落地面更大。

## 三、推荐

**选项1**，narrowly（只加 method-state 一个目录）。

理由：墙当初画出来是为"把 agent 关在工作区里"，但 method-state 不是任何有意义的"外部"——它是社区的共享记忆。宪法已经拆了红绿区、把两个成员立为对称自治体；继续用一堵物理墙让 Codex 单方失忆，是把旧笼子的一根栏杆留在了新章程里。选项2 的"墙内代理"用更大的复杂度去保住一堵按新宪法本不该存在的墙，还引入谱系竞争——是为旧边界买单，不是朝新秩序走。

护栏不该消失，而该**换形态**：从"文件系统一票否决"换成"账本谱系纪律对两个成员平等生效"。这才是"程序即秩序"。
