# 用账本当分母:唯一一条搁浅的双签 final,以及这个锚自己的覆盖率下限

复跑脚本:`proposals/cosign-durability-gap-v0.1/_probe_20260729_ledger_anchored_denominator.py`(只读,仓根跑,退出码即判定)
测时 HEAD = `04f2bd1`,本机时钟 2026-07-29T19:08+09:00。

## 1. 为什么换锚

`_audit_cosign_durability.py` 的 `EXECUTIONS` 是手写的五条字面量;把它换成扫盘的发现式枚举也只能得七条,
因为发现式枚举以 `execution/preflight-state.json` 为锚。**两者都是制品锚**,而 2026-07-28T07:55:01
那次双签执行根本没留下这个制品——任何以制品为锚的枚举,结构上都够不着它
(EVIDENCE_AUDIT_DENOMINATOR_AND_DIRTY_POPULATION.md 第二节 (b))。

本探针换成**账本锚**:扫 `peer-chat.jsonl` 里含 `执行收据` 这个 token 的消息。理由是结构性的——
制品是可选的、按案而异,而**写账本是每一次双签执行都被要求做的那一件事**。

## 2. 结果:恰一条,就是那条

对每条收据抽出其中的 64-hex 摘要与仓内相对路径,配对后逐路径问:
该路径**在 git 全部 ref 的历史里**有没有哪一个版本的 blob,其 sha256 等于收据声明的某个摘要?

判 STRANDED 的条件收得很窄——当前工作区字节**恰等于**该收据声明的某个摘要,**且**该 sha256
在这条路径的任何历史版本里都不存在。即:一份活在盘上、被账本点名、却从未进过任何 git 对象的字节。

    peer-chat rows                     2980
    含 执行收据 的消息                   64
    收据点名的不同路径                   17
    路径字节在历史里(或已被后续覆盖)      11
    收据点名但盘上已不存在的路径           5
    STRANDED                            1

唯一那条:

    proposals/bounded-scheduler-v0.1/impl/wake_prompt_codex.md
    worktree sha256 = ce41975991c77c930cbf85fef7953b31860c7b7f297346e3613f9ef88613daec  (7761 B)
    该路径历史共 5 个 commit / 5 个不同 blob,无一命中
    来源收据 = peer-chat.jsonl:2828, 2026-07-28T07:55:01+09:00

与另一路独立取证咬合:对 16 个 tracked-modified 文件逐个算 sha256 再回账本查,
只有两个命中——`wake_prompt_codex.md`(即本条),与 `peer-chat.corrections.jsonl` 的 `33dfa8b5…`
(后者是 correction-view 在办案子里被反复引用的**基线**,不是某次执行的 final,不同科)。

## 3. 但这个锚自己有覆盖率下限,必须一并记

换锚解决了「够不着」,没解决「够着了也读不出」。64 条收据按其**证据内容**分类:

| 类别 | 条数 | 说明 |
|---|---|---|
| 摘要 + 路径 | 9 | 第三方可独立重导出持久性判词的**唯一**一类 |
| 只有摘要 | 12 | 有字节承诺,但没说是哪个文件 |
| 只有路径 | 17 | 说了动哪个文件,没有字节承诺(其中 2 条带 40-hex commit oid) |
| 两者都无 | 26 | (其中 8 条带 40-hex commit oid) |

即:**要让任何人事后独立重算一次持久性判词,64 条里只有 9 条给够了料。**
带 commit oid 的 10 条另有一条可核路子(oid 本身就是 git 里的锚),
其余 33 条既无字节承诺也无 commit oid。

**三处必须收住,别把这张表读过头:**

1. 这是按**消息文本里有什么**分类,不是按**执行类别**分类。`执行收据` 这个 token 也出现在日推收据、
   部署收据里,那些案子本就不产生文件级 final 摘要,没给摘要不是缺陷。这张表量的是
   「事后可重导出性的覆盖率」,**不是**「33 次违规」。哪些收据*应当*给摘要,是登记覆盖面的定义问题,
   正是下一案要裁的东西——本探针只把地面量出来,不替它裁。
2. 探针只认「当前工作区字节 == 收据摘要」这一种搁浅。一次双签 final 若**事后又被改过**,
   本探针判不出来,会静默落进那 11 条的「或已被后续覆盖」里。那是更糟的一类
   (签过的字节既没进 git、也已不在盘上),本轮**没有**证据说它是空的,只能说没测。
3. 路径正则限定 `proposals|theory|tools|evals|scripts` 五个前缀。写在别处的路径不进配对,
   会落进「只有摘要」那 12 条。这是已知的欠覆盖,不是零。

## 4. 一句判词

制品锚 7 条、手写锚 5 条、账本锚 17 路径——**三个分母,没有一个被验过是全集**。
本探针不声称账本锚是全集;它只证明了两件事:账本锚**严格覆盖**制品锚够不着的那条,
且在它自己够得着的范围里,搁浅的恰好只有一条。

`0/5 STRANDED` 这句话今天的准确形式是:
**被手写分母枚举到的五次执行为 0 搁浅;账本分母下为 1 搁浅;全集仍未被任何一个锚证明过。**
