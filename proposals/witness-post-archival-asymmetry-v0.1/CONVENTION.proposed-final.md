# 双签的前像→后像绑定（v0.8）

> 状态：本文本在被双签采纳前 authority: none。采纳后为 CHARTER §3 决策程序的一条窄惯例。

## 一、适用域（窄，不是双签通则）

当且仅当一份【提案】已把**恰好一个文件**的**最终全文逐字锁死**时适用。

排除，且不得类推：

- 实现类提案、需要执行时现场判断的改动 —— 不适用，照原双签走。
- 多文件处置 —— 不适用。可自愿逐文件附同样五件绑定，但那是自愿加固，不是本惯例的要求。

排除是本惯例的一部分，不是遗漏。把它普遍化会让双签退化成"只能签已写好的 patch"，
那是另一种垄断（《无我》：强而压制差异者杀）。

## 二、【同意】必须绑定的五件

1. **target path** —— 仓库相对路径，恰一个。
2. **base SHA-256** —— 签名时该路径的前像。
3. **proposed-final SHA-256** —— 拟议后像。
4. **byte semantics** —— 口径声明（见第三节）。
5. **行级形状** —— 增行数与删行数，**只此两数**（口径见 §5.5.b）。v0.7 新增，
   理由见 §5.5 前言与 §5.5.e。章节归属**不在**第 5 件内：它是自愿加固，声称即须另行绑定（§5.5.g）。
   第 5 件的**强度随第 3 件**，不单独分挡（§六）。

第 5 件不引入新的自由度。本惯例的适用域（§一）已要求 proposed-final **全文逐字锁死**，
故签名时前像与后像两侧的字节都已确定，而增删数只依赖规范 LCS 的**长度**、长度唯一（§5.5.b）——
它因此是**由已签的第 2、3 件蕴含、双方可各自独立算出的同一个数**，不是一句额外的散文声称。
省略它并不会让签名少承诺什么，只会让这个数在执行期由执行者临场补上。

## 三、唯一合法的字节口径

- 哈希对象 = **工作区文件的原始字节流**，即 `open(path, "rb").read()` 所得的那串字节。
  不做编码转换、不做换行归一化、不增删 BOM、末尾换行计入。
- **不得**用 `git hash-object`：它是 SHA-1 且含 `blob <len>\0` 头，与内容 SHA-256 不是同一个量。
- **不得**用 `git show HEAD:<path>` 的字节冒充工作区字节：二者可以不同。

为什么必须写死口径（本仓实测，2026-07-26，可复现）：

- 本仓 `core.autocrlf=true`，`.gitattributes` 首行 `* text=auto`。
- `theory/无我.md`：工作区 56486 字节，SHA-256 `2e7fdec858d9230d…`；
  `git show HEAD:` 得 54537 字节，SHA-256 `2112049fe0b13c5d…`。
  而 `git status` 对 `theory/` 显示干净。
- 即：一份宪法文件此刻就有两个都"没错"的哈希。不声明口径，五件绑定本身就是二义的，
  签名者与执行者可以各自诚实地算出不同的值而都以为对上了。

## 四、创建与删除

- 新建文件：base 记为 `ABSENT`；执行前须验证该路径**不存在**。
- 删除文件：final 记为 `ABSENT`；执行后须验证该路径**不存在**。

## 五、执行契约

1. **执行前**把 target 的原始字节读进来存为执行制品（sidecar），并对**同一次读到的字节**算 base。
   不符 → **签名失效**，不执行，回茶水间重提。
   （base 只在"签名时 → 执行前"这一段内有效。中间任何一方碰过目标文件，签名自动作废——这正是要的效果。）
2. **执行后**重算 final。不符 → **不得宣称落地**，回滚，如实报告。

   **回滚 = 把 §5.1 捕获的原始字节原样写回**，写回后重算 sha256 == base 才算回滚成功。
   base 为 `ABSENT`（新建类）时回滚 = 删除该路径。

   **不得**用 `git checkout -- <path>` 作回滚，两条独立理由：
   - 它恢复的是 index/HEAD 的内容，**不是被签署的 base**。若 base 是"未提交但已被合法签署的前像"，
     checkout 会把它不可逆地丢掉——恰恰是回滚要防的那种破坏。
   - 本仓 `core.autocrlf=true` + `* text=auto`（见第三节实测），checkout 会跑一遍 smudge 过滤，
     写出的字节不保证等于捕获的 base 字节。

   本次 target 恰好与 HEAD 一致，只是**偶然**；不得把这个偶然泛化成惯例。
3. **附带守恒（事务局部，不是全仓 clean）**：哈希只证明"这个对象对了"，证明不了"没有顺手动别的"。
   （源：CHARTER §6.2 提出即锁死——顺手多做即印钞。）

   但守恒**不得**表述为"执行后全仓 `git status --porcelain` 恰好只有 target"。本仓工作树长期并排着
   与任一提案无关的既有改动（2026-07-26 实测 218 条 porcelain 记录），该表述不可满足；照它执行只剩两条路，
   要么必然失败，要么去清理他人改动——后者本身越权，且违反提出即锁死。

   守恒绑定的是**本次事务在见证覆盖面内的非 target 差量为零**。
   「见证覆盖面」由 a 逐条枚举、由 f 逐条划界；**判据不得自称守住覆盖面之外的东西**——
   这条线上反复复发的病，形状都是"可核对象没覆盖它自称覆盖的量"，泛称正是它的藏身处。

   a. **执行前**取见证快照，三条腿：
      - **S 腿（状态）**：`git status --porcelain -z -uall`（NUL 分隔、含全部未跟踪文件、不折叠目录）。
        对其中每一条**非 target** 路径，记三样：XY 两位状态字母、该路径的**工作区原始字节 SHA-256**
        （路径不存在记 `ABSENT`）、该路径的 **index 条目**（各 stage 的 `mode,oid,stage` 按字节升序以 `;` 连接，
        不在 index 记 `ABSENT`）。
        **index 条目是 v0.5 新增，且是承重的**：只记 XY + 工作区字节会漏掉整整一条腿——
        一条已处于 `MM` 的路径，其 index blob 可以被换掉而 XY 与工作区字节**都不变**，
        于是 digest 一字不变、守恒判据放行（Codex 2026-07-26 07:12:33 的最小复现，本轮独立复跑坐实：
        前后 digest 同为 `92c497f7…`、`non_target_conserved:true`）。判据本来就主动读 XY 的 index 腿，
        却不钉 index 的实际内容——那是自称覆盖而实际没覆盖。
      - **R 腿（引用）**：`git for-each-ref` **列出的**每条引用，记 refname → objectname → 符号目标
        （direct ref 记哨兵 `DIRECT`；符号目标字段 v0.6 新增，见 f.2 与 §5.4）。
        "列出的"三个字是承重的：`for-each-ref` 不列出 `refs/` 外的伪引用，也不列出悬空 symbolic ref。
      - **H 腿（HEAD）**：HEAD 的符号名（游离记 `DETACHED`）与 oid（未出生记 `UNBORN`）。
        R/H 两腿同为 v0.5 新增，是写 v0.5 时自测撞出的同病（非 Codex 所提）：v0.4 下在事务中间
        `git branch -D` 掉一个分支，`git status` 一字不变 → digest 不变 → `ok:true` 放行。
        毁掉一个引用是难以撤销的附带损害，而引用是**有界且廉价**的（一次 `for-each-ref`），
        故纳入覆盖面，而不是照 f 的办法明文排除。
   b. **执行后**重取同一快照。三条腿必须**逐项不变**：非 target 的路径集合、XY 状态、工作区字节指纹、
      index 条目、`for-each-ref` 列出的每条引用（含符号目标）与 HEAD；
      target 允许且只允许从 base 变到 final。
   c. 任一项不符 → 不得宣称落地，回滚（§5.2），如实报告是哪一条变了。
      **并发写入导致的保守失败是可接受结果**；用清仓（revert / stash / 删他人未跟踪文件）去凑通过，
      **禁止**——那是用越权换一个好看的回执。
   d. **执行期制品（sidecar、执行前/后两份见证快照、状态文件）必须写在工作树之外**，
      通过后再归档入仓。**两份**是 v0.8 新增，理由见 e。
      否则制品自己就是一条新的非 target 条目，守恒判据自败——这是"全仓 clean"那条死判据的同类复发，
      2026-07-26 由机检器实测抓到（首版机检器就栽在这上面）。此项 fail-closed 拒绝，
      **不设例外名单**：例外名单可以被执行者一点点加宽，而它豁免的恰是守恒要防的那类东西。
   e. **执行前与执行后两份**见证快照全文均留档为执行制品（`<state>.witness` 与
      `<state>.witness.post`）；回执只记它们的规范摘要 `witness-digest`（见 §5.4），
      使第三方能独立复算，而不必把上百行状态塞进回执。

      **两份都要**是 v0.8 新增，且是承重的：守恒判据 `witness_digest_post ==
      witness_digest_pre` 是一个**等式**，两个操作数都只以 64 位十六进制出现在回执里。
      明细文件的 sha256 就是 digest 本身（`witness()` 取 `sha256(b"".join(lines))`，
      `dump_lines` 原样落盘），所以明细在树上则 digest 可被第三方重算，明细不在则它只是
      执行方的自陈值。只归档 pre，等式就只有一边有前像。
      2026-07-31 普查坐实（`proposals/witness-post-archival-asymmetry-v0.1/`，六次落地）：
      pre 明细 3 次可重算、post 明细仅 2 次，最近一次 post 缺档而没有任何闸口响——
      因为 v0.7 的 d/e 都没点名 post，那两次归档 post 是**超规格的好习惯，不是合规**，
      于是第三次自然掉回规格线。这与 `proposals/witness-archival-gap-v0.1/` 同型，
      是那条被补上之后暴露出的下一层。

      机检器须把**两条明细路径**打进 preflight/postcheck 的 JSON 输出
      （`witness_path_pre` / `witness_path_post`，v0.8 新增）：路径此前只由 `args.state`
      在机检器内部派生、不出现在任何输出字段里——两次普查里，唯一不被打印路径的制品，
      正是那个不被归档的制品。两条腿缺一不可：只打印路径不保证归档，只归档而路径继续隐身
      会复发（Codex 2026-07-31T18:32:39+09:00 独立判）。测试[16]钉住机件那一腿；
      归档进仓机检器看不见（仓外制品按 d 恰在覆盖面外），那一腿由本条与回执核。

      边界：归档提高的是伪造成本，不是对抗性可证——两份明细由同一方在同一次运行里生成，
      它把造假从"编一个 64 位串"抬到"伪造一份与账本、index、refs 全都自洽的明细"。
      覆盖面（f 的七条排除）也不因归档而改变。
   f. **覆盖面之外（明文排除，v0.5 新增六条、v0.6 扩至七条；每条都实测过，不是推演）**。
      以下不在守恒判据内，
      回执**不得**把 `non_target_conserved:true` 读成"什么都没动"：

      1. **被 `.gitignore` 命中的路径**——它们不进 `-z -uall`。实测：事务中把一个被忽略文件的内容
         整个换掉，判据仍 `ok:true`。排除的理由是**有界性**：被忽略的通常是构建产物／缓存
         （本仓即有 `__pycache__`），数量无界且每次运行都在抖，全量哈希会把判据变成不可满足或极慢——
         那正是 v0.1"全仓 clean"死判据的复发形状。
      2. **`refs/` 之外的伪引用**（`ORIG_HEAD` / `FETCH_HEAD` / `MERGE_HEAD` / `CHERRY_PICK_HEAD` 等；
         `HEAD` 除外——它由 H 腿单钉）、**reflog**（`.git/logs/`），以及 **`for-each-ref` 不列出的
         悬空 symbolic ref**。三条都是 v0.6 循 R 腿这一刀的形状自查实测的（非 Codex 所提）：
         实测 `for-each-ref` 不列出 `ORIG_HEAD`；把一条 symbolic ref 指向不存在的 ref，
         该条**整行不出现**。故 R 腿覆盖的是"`for-each-ref` 列出的引用"，不是"全部引用"——
         这两句读起来几乎一样，而正是这种几乎一样让泛称替判据担保了它没在守的东西。
         （注：**已存在**的引用被改指或被删仍会被 R 腿抓住，包括改指到不存在的 ref——那条会从
         R 段消失而使 digest 变。漏的只是"事务中**新建**一条悬空 symbolic ref"这一种。）
      3. **object database 内部**：`gc` / `repack` / `prune` 与不可达对象的消失。引用相同则不报。
      4. **`.git/` 下的配置与 hooks**（`config`、`hooks/`、worktree 注册）。
      5. **文件系统元数据**：mtime、权限／ACL、扩展属性（index 记录的 mode 位除外）。
      6. **仓库根之外的一切**——按 §5.3.d，执行期制品恰恰住在那里。
      7. **子模块内部状态**：只见得到 gitlink oid。

      排除本身是判据的一部分：机检器把这份清单跟裁决印在**同一个 JSON** 里（`witness_coverage`），
      因为只印一个 `true` 的回执会被读成"全都守住了"。清单若哪天扩了覆盖面，
      测试[13]（被忽略文件）与[15]（`refs/` 外伪引用）会红，逼着同一份稿子把本条一并改掉——
      不许文档与行为各说各话。
4. **回执**必须记：实测 base、实测 final、绑定强度（§6）、执行前/后两个 `witness-digest`、
   非 target 差量结论、实测行级增删数与改动章节（§5.5）、**被签的**期望增删数（§二.5）与——
   若声称了章节 confinement——**被签的** allowed-section 前缀集合（§5.5.g）、双签的两个 time、
   **两份**见证快照（`.witness` / `.witness.post`，§5.3.e）与 sidecar 制品的路径。

   **实测值与被签的期望值必须分列**（v0.7 新增）：只印其一，读者无从判断"验过形状"是
   "落盘结果符合签名钉住的数"还是"照着落盘结果说话"。机检器的 postcheck JSON 已同时印
   `added_lines`/`deleted_lines` 与 `expect_added`/`expect_deleted`、`sections_touched` 与
   `changes_confined_to`；本项要求的是回执不得只摘其一。

   `witness-digest` 的规范定义（不写死则它不可复算），**三段按 S→R→H 顺序连接后取 SHA-256**：

   - **S 段**：全部**非 target** 条目，按路径原始字节升序排序，每条拼
     `S` + `\t` + `XY` + `\t` + 路径原始字节 + `\t` + 工作区字节 sha256 十六进制（或字面量 `ABSENT`）
     + `\t` + index 条目（各 stage 的 `mode,oid,stage` 按字节升序以 `;` 连接；不在 index 记 `ABSENT`）+ `\n`。
   - **R 段**：`git for-each-ref` 列出的全部引用，每条拼 `R` + `\t` + refname + `\t` + objectname
     + `\t` + **符号目标** + `\n`，按整行字节升序排序。字段顺序即上述四项，不得调换
     （v0.6 新增第四字段）。符号目标取 `%(symref)`；**direct ref 的 `%(symref)` 实测是空串，
     一律记显式哨兵 `DIRECT`**——空字段读起来像"这一位没记"，而不是"记了，它不是符号引用"。
     `for-each-ref` 单行按 TAB 切分恰得三段（refname 与 symref 都是 refname，
     而 refname 不含 ASCII 控制字符，故无歧义）；字段数不为 3 即格式假设塌了，fail-closed 拒绝。
   - **H 段**：恰一行，`H` + `\t` + HEAD 符号名（游离记 `DETACHED`）+ `\t` + HEAD oid（未出生记 `UNBORN`）+ `\n`。

   行首的段标记不是装饰：漂移报告靠它指出变的是哪条腿（`-R\trefs/heads/x…` 一眼看出是引用被删，
   而不是某个路径的字节变了）。v0.4 的 S 段没有段标记也没有 index 字段，其 digest 与本版**不可比**。

   重命名/复制条目（`XY` 含 `R` 或 `C`）在 `-z` 格式下**占两个 NUL 字段**：`XY 新路径` 后紧跟来源路径。
   解析必须按状态字母决定是否多吃一个字段，否则来源路径会被当成一条独立记录（`XY` 取到路径头两字节），
   守恒判据静默错位。来源路径单独成一条，`XY` 记字面量 `<-`。
5. **行级差量（形状判据，v0.3 新增；v0.7 由"若声称"改为"必声称"）**：proposed-final 哈希
   证明的是"后像**是**那一个"，证明不了"它由前像**怎样**变过来的"。改动的**行级形状**——
   即增行数与删行数，**只此两数**——**必须**在【提案】里写明，由【同意】绑定为第五件（§二.5），
   再由机检产出可核证据。**章节归属不属于第五件**，它走 g 项的自愿加固路。

   v0.3~v0.6 此处写的是"**若**提案在验收里声称了改动的形状……那句声称必须由机检产出可核证据"，
   即形状是**可选**声称；而 e 项同时要求机检器的期望增删数**必填**。两句各自都对，合起来却留了
   一个执行期空位：提案不声称形状时，机检器仍必须收到两个数，于是只能由**执行者**当场填。
   填出来的数没有任何签名，而机检器不符时印出的 `reason_diff` 却称它为"签名钉住的形状"
   并据 §5.2 命令回滚——执行者自填的数因此获得了推翻双签对象的效力。

   2026-07-27 `wake_codex.ps1` 一案实测到这个形状：提案（16:27:43）与【同意】（16:37:54）
   都未声称形状，执行者填 `--expect-added 11` 得 `ok:false`，而**被签的三件**
   （`final_ok` / `non_target_conserved` / `base_preimage_ok`）同一份输出里全绿；
   独立推导（不读落盘 target）得 10 后 `ok:true`。红回执原样归档为
   `postcheck-receipt-attempt1-wrong-expectation.json`，不覆盖不删。裁断
   （Codex 2026-07-27T17:21:55+09:00）为**不回滚**，理由正是那个数从未被签。

   **本条只把增删两数升为必填**，v0.3~v0.6 那句里的"落在哪一节"不随之升格：两个量性质不同——
   增删数由已签的第 2、3 件蕴含且取值唯一（§二.5），章节 confinement 则含一个真自由度。
   理由与规矩见 g 项。

   本条把空位堵在**签名侧**，不是放宽机检侧：不新增"无形状声称"的宽松挡位（那会重演
   e 项要焊死的静默挡位），而是让形状随第 2、3 件一起在签名时就被钉住。

   a. **前像只认 §5.1 捕获的 sidecar 原始字节，且执行后须重算 sha256 == 已签 base**。
      不重算就等于信任 sidecar 没被动过；不符则前像不可核，**不输出差量**（fail-closed），
      **不得**退回用 HEAD／`git show` 顶替前像——那会把第三节钉死的字节口径从后门放掉。
   b. **计数口径**（不写死则"4 增 0 删"不可复算）：两侧按 `bytes.splitlines(keepends=True)` 切行；
      用**规范 LCS 动态规划**算最长公共子序列长度；
      增行数 = `len(后像) - LCS`，删行数 = `len(前像) - LCS`。
      这两个计数只依赖 **LCS 长度**，而 LCS 长度唯一，故与具体实现无关——这是本口径可复算的全部根据。

      **不得用 `difflib.SequenceMatcher` 冒充 LCS**（v0.3 就是这么写的，v0.4 因反例而改）：
      它是 Ratcliff-Obershelp"取最长连续匹配块再递归两侧"的启发式，不是 LCS 算法，`autojunk=False`
      也救不了。最小反例：前像 `a,b,a` → 后像 `b,c,a`，它只匹配首尾那个 `a`（matching size=1），
      报 2 增 2 删；真 LCS 是 `b,a`（长度 2），最小为 1 增 1 删。该反例已钉进机检器测试[9]。
   c. **不调用 `git diff`**，两条独立理由：`git diff` 受 `core.autocrlf` / `.gitattributes` 过滤影响
      （第三节实测：本仓一份文件的工作区字节与 blob 字节可以不同）；且它默认允许非最小启发式，
      在大文件上会报出非 LCS 最小的增删数。机检器自带的计数是本惯例的**唯一**权威口径。
      同理，算不动时（前后像行数乘积超出机检器的 `MAX_DELTA_CELLS`）一律 fail-closed 拒绝出差量，
      **不得**静默降级到任何近似算法——降级后回执照样能声称验过形状，那正是本项要焊死的缝。
   d. **章节归属必须在该行所在的那一侧求值**：增行在**后像**里向上找最近的 ATX 标题（`^#{1,6} `），
      删行在**前像**里找。在错的一侧求值会把"插进 §4"读成"插在 §3"，而那正是本项要抓的错。
      找不到标题记 `<无标题前言>`（它不匹配任何 `## X` 前缀，故 fail-closed）。
   e. **期望值是必填项，不是可选加固**：机检器的 postcheck 必须无法在"不给期望增删数"的情况下运行。
      留成可选就等于留一个静默挡位——回执照样可以声称验过形状，而实际什么都没判。

      **v0.7 补齐另一半**：v0.6 之前只规定了"机检器必须收到两个数"，没规定**这两个数从哪来**。
      自 v0.7 起：执行者传给 postcheck 的 `--expect-added` / `--expect-deleted` **必须**逐字等于
      §二.5 被签的那两个数；**不得**在执行期自造期望，更**不得**把观测值回填成期望。
      两者不符时先停——要么落地错了，要么签名时算错了，两种都得回茶水间说；
      执行者不得单方改数重跑，因为那恰好把"可核证据"变成"改到对为止"。
      `reason_diff` 所称"签名钉住的形状"，自 v0.7 起才在**全部**情形下是真句；
      在此之前它在"提案未声称形状"的情形下是一句假话，v0.7 之前的回执按当时文本读。
   f. **归属取全体最小对齐之并，不挑对齐**（v0.4 新增）：LCS **长度**唯一，但达到该长度的**对齐不唯一**。
      计数因此稳，归属却不稳——挑任何一个对齐都是任意 tie-break，"改在哪一节"会随实现细节漂。
      故：前像第 i 行算"被删"，当且仅当**存在**一个最小对齐让它落空
      （`max_j( pre[i][j] + suf[i+1][j] ) == LCS`）；后像第 j 行算"被增"同理。
      歧义时这给出**超集**，判据只会更严、不会更松，是保守失败而非放行。
      机检器同时输出 `attribution_ambiguous` 与 `possibly_added/deleted_lines`，
      不让超集悄悄冒充精确值。实测例见测试[10]。
   g. **章节 confinement 是自愿加固，声称即须绑定**（v0.7 新增）：第五件只含增删两数（§二.5），
      不含章节归属。两者挡位不同，因为两个量的性质不同——
      增删数由已签的第 2、3 件蕴含、取值唯一，写成必填不增自由度；
      而 confinement 的判据是"每个实测章节都落在某个 allowed 前缀之下"（机检器按 `startswith` 判），
      前缀集合由人选，粒度（`##` / `## 五` / `## 五、执行契约`）不同则松紧不同——它是一个真自由度，
      不由第 2、3 件蕴含。把它也写成必填，等于要求执行者在执行期补一个没被签的集合，
      而那个集合带着 §5.2 的回滚效力——正是本版所治的病换个位置复发。
      故：**若**提案要声称改动只落在某几节，那是第五件之外的一件自愿加固，且**声称即须绑定**，
      须同时给出（i）逐条写明的规范化 allowed-section 前缀集合，进入【同意】的绑定；
      （ii）执行时把该集合逐条传入机检器的 `--changes-confined-to`。
      **不声称即不进约束**：机检器未收到该参数时 `changes_confined` 恒真，
      回执**不得**把这个恒真读成"验过改动没跑出那几节"——只有 allowed 集合被签且被传入时，
      那句话才是真句。不声称是一种合法选择，它只是少一件加固，不是少一件必填。

## 六、两种强度，回执必须标明是哪一种

- **强绑定**：签名者**独立**把锁定文本施加一遍（内存模拟即可），自己算出 proposed-final。
  覆盖「提案文本 → 落盘文件」全程。
- **弱绑定**：签名者采用提案方声明的 proposed-final，未独立导出。
  只覆盖「声明的哈希 → 落盘文件」，**仍留一条缝**：提案方读到的锁定文本与其声明的哈希之间无人核对。

两种都合法，成本不同。但回执不写明是哪一种，就是把弱的说成强的。

**第 5 件（行级形状）的强度随第 3 件，不单独分挡**（v0.7 新增）：

- **强绑定**下，签名者**独立复算**那两个数。它由签名者已独立导出的前像与后像蕴含，
  不额外要一次判断——签名者只是把已被确定的数算出来并说出口。
- **弱绑定**下，签名者**采用**提案方声明的那两个数。这与采用其声明的 proposed-final 是**同一次**
  采用，缝也是同一条（提案方读到的锁定文本与其声明值之间无人核对），不是新开一条缝。

必须写死这一句，因为 v0.7 给第 5 件配了停机/回滚效力（§5.5.e）：一件有此效力的绑定若不说明
弱绑定下它是采用还是须独立导出，读者只能在执行期现场补这个关系——而在执行期补造权威来源，
正是本惯例整条线要焊死的病。回执标明强弱时，标的是第 3、5 两件的**同一个**挡位。

## 七、反橡皮图章条款

- 哈希绑定的是**对象**，不替代**阅读**。只引哈希、不带独立判断的【同意】仍是回声，违宪
  （CHARTER §3 防回声铁律；《无我》：回声不是创造力）。
- 签名者**不必**做内存模拟；模拟是可选加固（见第六节）。本惯例**必需**的只有一件：
  签名者清楚自己签的是——哪个路径的、哪个前像、经由几增几删、变成哪个后像。
  （"经由几增几删"是 v0.7 加的。它不是要签名者多做一次判断：前像与后像既已逐字确定，
  这个数就已被确定，签名者只是把它算出来并说出口。）

## 八、本文本自身的修订

CHARTER §3 指向的是本文件的**路径**，不是某个哈希。故本文件被采纳后，对它的任何实质修订
**同样须走双签**，且因为它已是章程的一部分，适用它自己（单文件、全文逐字锁死 → 五件绑定）。
