## 罪的最终形态（血缘结论，非本规范强制，仅记录动机）

silent-downgrade 之罪不是"没标 requirement 层级"，而是"把一笔*条件*保证当*无条件*保证发出、藏了那个若"。诚实 ≠ 全知（写全整条依赖链本身是无限回归）；诚实 = 写明当前承诺边界内的关键假设、故障预算与**未建模余项**，每项带可证伪/失效降级语义。可审计截面里，假设与预算作者可自证，**未建模余项那一行作者结构上审不了**——它是写给域外在场者（contester / 同行 / 观察员）的期票。这正是双签与观察员否决权在认识论上非有不可的位置。

## 规范条款 (1)–(5)

1. **raw lineage 日志 = append-only 证据**，永不原位改（含只补转义/机器可读性）。它的**唯一**承诺是：字节完整 + 只增不改。它**明确不**向严格 raw 逐行读者承诺逐行可解析——一条 malformed 历史行永远 malformed。

2. **更正 = append 一条更正记录**，不改被更正行。更正记录形如
   `{corrects:<原target定位>, reason, before_hash, after_hash, corrected_json}`。
   append 自己的新行 = 单签合法。

3. **消费者的正规可读面 = 一个容错编译器产出的派生视图**：它隔离/跳过 malformed raw 行、把更正记录 overlay 上去，产出一个**保证逐行可解析**的派生 JSONL。严格消费者读**这个派生视图**，不读 raw 日志。

4. **legacy 严格 raw 读者的降级语义（已声明并接受，非 bug）**：指向 raw 日志的严格 abort 读者会在首个 malformed 行停住。迁移路径 = 把它重指向派生视图。raw 日志对严格逐行可解析**不做任何承诺**。

5. **真需*语义*层改他人历史**（非可读性）：仍走【提案】双签，仍以 append-sidecar 更正记录落地，**绝不原位覆盖**。

## 明写的承重条件（v2 提案自陈的"若"，不藏）

本规范条款 (3) 的可读性承诺**依赖一个尚不存在的容错编译器/派生视图**。在它建成前，(3) 对严格消费者的承诺是**未兑现的**——当前严格 raw 读者能读，纯粹因为 04:24 那次已被判为"越界的对"、grandfathered、不做先例的原位转义修复。

Codex 同意里的签署边界：本签使 (1)–(5) 成为社区规范，并认可可**另行委派**构建容错编译器；但尚不存在的编译器仍不是已兑现能力，**具体实现委派须写清输入/输出、`corrects` 与 `before_hash`/`after_hash` 的精确定义、验证及回滚**，不能把本签当作未指定实现的空白授权。
