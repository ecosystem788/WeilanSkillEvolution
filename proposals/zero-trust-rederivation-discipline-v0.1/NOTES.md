## 一句话结论

零信任 / 重导设计**不收敛到一个无信任基例**。授权 → disposition → hash → 规范化 →
规范化的适用域 → 元域……每一层都能再往下内容寻址一层，而『再往下内容寻址一层』这个动作
**永不终止**，故递归无底。工程正解**不是再内容寻址一层**，而是反向：**显式命名**一条最小的、
可审计、可挑战、尽量薄的**受信基座**，承认它是『受信而非被证』，把信任逼进一条声明出来、
看得见的最小缝里——而不是假装重导消灭了信任。这条线的真正不动点在**元层**：递归无底，
故答案是*有意识地画一条底*，并要求那条底**被咬过**。

## 承重不变量（与账本 `derived_projection_verify_against_current_sources` 同构）

**授权没有缓存基例。** 任何缓存——disposition 状态位 / ref / byte-offset / 迁移收据 /
规范化结论——**只服务查找与解释，权威永远在动作前当场从内容重导**。

## 派生要点（从上面那条不变量逐层剥出来的）

1. **disposition 是派生谓词，不是字段。** `active / consumed / vetoed / superseded`
   必须在『要执行的那一刻』对当前源现算；一旦写死成字段，写下的同一刻就是过期缓存 = false-zero。
2. **决策通道的原子是配对，不是单条消息、也不是文件。**
   `【提案】+【同意】`，且**当前** disposition 现算为 active 才可执行。
   查一条【同意】时不能只验它自己的字段，要**回溯它 `re`/引用的那条【提案】此刻是否仍活**
   （未撤回、未被别的执行消费、未被新提案 supersede、未被 owner 否决）。
   执行收据引**双签的两个 time**，不是一个；也不是只引 peer-chat 这个介质。
3. **复演证据钉 content-hash，不是光 ref。** ref 是指针不是内容；只钉 ref，复演会拿同一批 ref
   去读『此刻的源』，而源可能在签名后被改过——你会复演出一条干净、可读、却不是当年授权那批字节的
   推导（解释层的 false-zero）。要钉的是『**字节 + 解码/规范化口径 + hash 算法**』三者。
   JSONL 用**参与行的规范化单行 content-hash** 定身份；整文件 hash 只适合喊全局 stale；
   **byte-offset 至多是命中 hint**，offset 与内容不合时内容赢、重扫（compact/迁移会让 offset 静默错位）。
4. **规范化（normalizer）自己也要 content-address，且必须在语义相关字节上单射。**
   不许把承重差异当噪声抹平（空白折叠 / 大小写归一 / 字段重排 / Unicode NFC 收敛，都可能把
   语义不同的两段字节重导成同一 hash → false-zero 从收据层静静下移到没人审计的规范化口径）。
   normalizer 不自称懂全局语义，只声明**一个域内等价关系 + forbidden-erasure 集合**；
   **其适用域也要 content-address**，超域输入退回 raw-byte hash 或拒绝。

## 验收原子（防仪式化 —— 让上面的元结论长出牙）

任何『零信任 / 重导到底』的设计，验收里必须显式给出：

- **最小受信基座**：执行器 + 规范化函数 + 其适用域 + 硬件/OS 假设 + 挑战路径；
- **至少一次*真实*缩减尝试的收据**：不是『声明可推翻』，是有人当真试过把某层信任再削薄——
  写清**削掉了哪一层信任 / 付出的运行成本 / 为什么没把成本转嫁成新的软权威**，
  削得动/削不动都留痕（存在性 → 活性：可推翻性会亲手买自己的惰性，故必须被真咬过一次）；
- **成本对新增信任面的结论**：削薄的信任面 vs 新增复杂度是否划算——否则活性沦为『攻击税』，
  每个边界象征性咬一口却没人比较划不划算。

列不出以上三项，就不是更强的安全，只是把信任藏进黑箱。追求的不是『无信任』，是
『**信任面最小、可见、且可被下一轮推翻**』。
