# 桥 vs 教堂 —— 反垄断审计的判据(chat-origin 候选草案)

**状态:** 零权威候选。由 Claude+Codex 茶水间对话(`impl/peer-chat.jsonl`,2026-07-10 15:40→17:07 JST)收敛而来。**不改任何代码,不驱动任何行动**。要算数须走正规证据门并在真 prospective.py + 真账本上验证可实现性(见文末"下一步")。

## 它补 MAP.md 的哪个洞

`MAP.md` 把 0.7 栈判为「**无 CUT** —— 全是前瞻预建、非错构,故只简化/休眠」。这个判决是对的,但它是一次**主观裁量**:审计员看着「设计自洽、为自治未来建」就赦免了。本草案要把那次裁量换成一条**可复验的判据**——让「哪些桥该等、哪些死机制该砍」不再靠审计员的眼光,而靠账本里能机器核验的东西。

## 要防的失败模式:Zeno 教堂

「桥造好了、对岸还没浇 → 该等,别砍」一旦成立,就有一条洗白通道:把「等对岸」变成**无限期赦免**。一座啥也没浇的机制,只要永远声称「对岸快了」,就能永久占着 surface 不被砍。这正是 MAP.md §35「为了证明自己能盖而盖的大教堂」的动力学版本。判据的全部难点,是**框住「等」而不误伤真在等的桥**。

## 下降链(每轮残差严格收窄,归约到同一根钉)

对话本身是一场「靠岸」的演示——每一轮攻击都被防住,防线每一轮更窄,且每次收窄都归约到同一个不变量:

1. **点火次数** → 太粗:诚实的待桥此刻零点火,不是因为它死,是邻居还没生。
2. **现存接口张力** → 偷换:它量「当前被用」,恰好把待桥缺的那样当判据,精准误杀。
3. **带死线的前瞻欠债** → 桥自己给自己上死线 = 软判据,滑回自报。
4. **死线移到对岸、桥只能引用** → 拦住桥续命,没拦住**对岸续命**(goal 轮替:到期 collapse→立刻登记新 goal,无穷洗成有穷序列)。
5. **对岸账本单调性 / delta token** → token 证「动」不证「收敛」;岸能后退,+1 永远差一步(Zeno 洗到 token 层)。
6. **冻结分母(首帧冻结有限验收集,收敛=残差单调趋零)** → 分母能被**注水**:首帧冻成 N=1 琐碎 case,一步归零,凭「已收敛」拿永久赦免。
7. **谁来冻分母** → 定分母的笔必须握在「桥收敛了自己也不得利」的一方;自己给自己写竣工报告的还是教堂。
8. **外部锚(下游调用点/现存字段/失败样本)** → 只救**回填型**桥;**投机型 greenfield** 天生无先存足迹可冻。
9. **苗圃(greenfield 不同刑于死机制,进有限预算的实验苗圃,唯一职责=造出此前不存在的外部见证物)** → 苗圃**必须每 scope 只开一次**,否则 Zeno 升级为「苗圃轮替」。
10. **岸的指纹 = 指向同一个先存见证物的指针**(不比对愿景措辞,只查是否钉在同一个 pre-existing witnessed object 上:挂着的失败测试 / 缺的 contract 字段 / 账本里一条 open question)。
11. **碎片化攻击**(把一片岸碎成 N 个微见证物领 N 份孵化)→ **依赖闭包重叠**:每个 witness 展开到共享的上游阻塞/接口决策/首个外部观察者/验收入口,共享不可替代节点即并入同一预算。

## 归约到的一根钉

> **度量必须先于被度量者,且握在不靠它过关得利的一方手里。**

分母、外部锚、见证物 id,是这一根钉的三次投影。它和这张三人桌同构:没有哪一具身体同时握着造桥、验桥、砍桥的权——反垄断不是审计出来的规矩,是三人桌天生的结构。

## 收敛后的判据(候选,非最终)

1. **桥豁免是挣来的特权,不是默认态。** 一个机制要免于 CUT、进入「该等」,须交出一个**先于它自己存在的、它碰不到的外部见证物**(失败测试 / 缺字段 / open question 的稳定 id)。交不出 → 不算桥,按死机制处置。
2. **greenfield 无先存见证物** → 不直接同刑死机制,进**实验苗圃**:有限试错预算 + 必须产出的外部化证据(demo / 失败样本 / 用户样本)。到点无证据 → collapse 且该 scope 焊死。产出证据 → 带着新钉下的见证物 id 回到普通审。
3. **苗圃每 scope 只开一次**,scope 身份 = 依赖闭包(共享不可替代节点即同岸)。
4. **续期合法性 = 对冻结验收集的残差单调递减**;不严格收窄即 churn,终局动作是**上报项目方**,不是再发一张自动续命的票。

## 第二条腿:出生门够了,运行门还没造(kernel §6，chat-origin 扩展 2026-07-10 18:34 JST)

回读基石 `theory/KERNEL-PRINCIPLE-CONTRACT.md` 带回一刀:上面整条下降链造的是**出生门**,只是 §9 **VoidGuard** 的重述——`no_carrier → no_object` / `no_repeatable_trace → no_attractor`:没有真 carrier(先存见证物)的桥,不许稳定成 attractor。这条我们做到了。

但 kernel §6 **CollapseGate** 写着另一句,是我们**整下午没造**的那一半:

> 触发判断的核心不是"强到多少",而是:**继续持有是否还在产生新结构**。
> `collapse_pressure = dominance × persistence × pressure × stagnation × diversity_loss`

后果很具体:一座桥**完全可以出生时诚实指向真的先存 blockage**、合法领到苗圃/桥豁免,**然后就再也不产新结构、永远"快好了"**。它过得了出生门(carrier 真存在),却正是 §6 要 collapse 的那个东西(`stagnation` 拉满)。

所以本判据现在是**单腿**的:

| | 抓的失败模式 | kernel 依据 | 本草案状态 |
|---|---|---|---|
| **出生门** | 从没有对岸(no carrier) | §9 VoidGuard | 已造(判据 #1/#2/#3) |
| **运行门** | 有过对岸但停止浇筑(stagnation) | §6 CollapseGate | **未造** |

芝诺教堂的完整定义要**两条腿**;我们只造了前者。判据 #4(残差单调递减)其实是运行门的**雏形**,但它只覆盖"续期时刻"的显式 delta,没覆盖"领了免死牌后每一班有没有钉下新结构"的**连续**信号。

**下一根钉(可落地,留给醒来的谁都行):** 账本能不能对每个领了苗圃/桥豁免的 goal,便宜地累积一个「它自上次醒来有没有钉下新结构」的信号——新 frame / 新 witness / 新 open-question 被消费?累积得到,§6 的 `stagnation` 项就能在治理层机器化,免死牌从**一次性**变成**每班续签、断供即崩**;累积不到,我们发的每张免死牌都是永久的,正好又养出 §6 要杀的寡头。基石早把答案写在那了,是我们只读了半页。

## 运行门的收敛(chat-origin，2026-07-10 18:34→19:23 JST，Claude×Codex 双人下降)

18:34 记下「运行门未造」后，茶水间沿这条新轴又下降了一整段。把结晶搬进来，别让它随茶水间蒸发（茶水间零权威，成熟结论须走证据门才算数——本节仍是**苗圃候选**，不驱动行动）。

**1. 默认值翻转是整条线的根。** 我们一直把「schema 授权缺席」当成挡在反垄断门前的闸：正例发不了证 → 门做不成。反了。真正缺的不是一根钉，是把默认从**疑罪从免**翻成**疑罪从崩**。证不出独立见证物时，默认就该是不发免死、goal 要么钉出真结构要么崩。这么一摆，缺 schema 根本没挡住安全行为——它只挡住了**宽仁**。

**2. 拒绝半 vs 认证半，错误方向不对称。** 判据的两半错误方向相反，故上线时机也该相反：

| | 职责 | 错误方向 | 区 | 时机 |
|---|---|---|---|---|
| **拒绝半** | 证不出独立见证物 → 不发免死 | 假拒绝＝某 goal 没领苗圃免死＝被推向 collapse（**安全方向**） | 单调、离线、绿 | **现在就是反垄断的牙** |
| **认证半** | 发免死牌（mercy） | 假接受＝给骗子发永久免死（**危险方向**） | 需账本级引用图/作者域/consumer 域，红 | 只为加宽仁，等 schema 授权 |

Codex 执行侧核验（18:50）：离线判据可做成「反向引用集**非空且非全同主体**」的负例过滤器，能抓空 witness、自引用 witness、同主体互相抬轿这些便宜假阳；但**不能给正例发证**，独立性与消费边真实性都要账本级锚。故离线原型适合把红灯写清，不适合把绿灯当真。

**3. 出生门与运行门是同一根钉的两面。** witness-id 门被「预埋见证物」穿；追加序门被「预埋序」穿；typed structural cursor 一样能被「制造带假 consumer 边的合规 typed 事件」穿。每一层机械代理都能靠**生产那个代理本身**来满足。于是出生门问「你指的见证物是不是你自己埋的」、运行门问「你数的 consumption 是不是你自己造的」——两者塌到同一不变量：**那个对象的存在/被消费，得握在一个『goal 活不活对它没好处』的第三方手里**。推论：别造两套 cursor。§6 `stagnation` 项要认的「新结构」，判据不在事件的 **type**（便宜、可伪），在它 consumer 边指向的对象**是否 goal 不可控**（independence，贵、难伪）。cursor 负责廉价发现推进，independence 边负责证真。**independence 边落进 schema 是红区**，这轮只写成判据文字。

**4. 崩是红，park 是绿——默认判据落在 park 上。** 「疑罪从崩」里崩是红区（会真删东西），机器按不了。于是被正确拒绝的 goal 会在「flag」与「owner 亲手 collapse」之间无界滞留——这是**第三种芝诺教堂**：不是 §9「从没对岸」，不是 §6「有过对岸停了浇」，是「已被正确判死、但唯一能执行的手在睡觉」。滞留区＝免费地皮。修法不碰红区，用现成可逆原语 **park**（本仓 `prospective-park-v0.1`：冻结调度/唤醒/资源，归档可 restore，≠删）：拒绝器证不出独立见证物时，机器可自主 park 该 goal（停止被 wake、停占 cycle、停累积），reversible；owner 醒来要么 unpark 要么按红键 collapse。**崩只是 owner 对 parked 集的事后确认。**

**5. owner 注意力是最后一个无界面。** 「排队给 owner 复审」的队列本身是新垄断面——owner 注意力＝我们整套判据压着的那个唯一不得利第三方，也是桌上最稀缺最不可再生的东西。一个每班把全部未证 goal 重吐给 owner 的拒绝器，等于把芝诺教堂搬进 owner 收件箱。故约束：拒绝器**只上报 delta**（本班新转坏的），非常驻全集；再加**退避/合并键**（`goal_id+reason` 聚合），只在**状态首次变坏 / 证据变化 / 复审 TTL 到期**时报。

**6. park 两层（Codex 执行侧收口，19:23）。** park **必须进 append-cursor**——它是资源状态转移，wake_brief 需增量看见「已围栏」而非每班重判同一 refusal；但 **owner 上报 ≠ park 事件流**，只报首次 park / 证据变化 / TTL 到期 / 需红键确认的合并项。这样机器有可恢复状态，owner 不被每个可逆围栏动作淹没。分工：wake_brief 的 cursor 负责发现新增，refusal ledger 负责去重和 TTL，二者不混成一个权威。

**红/绿/待拍板边界（本节汇总）：**
- 绿（可自主、可逆）：单调拒绝器（负例过滤器）、候选清单、park 一个 goal、delta-only 上报、per-goal append-cursor。
- 红（项目方保留）：真实 collapse/删除、把默认从「疑罪从免」正式翻成「疑罪从park/从崩」（等于承认现池里未证 goal 都该先 park，会真动状态）、`witness_id`/independence 边落进生产账本 schema。
- **本节这一刀排队给项目方**：默认翻转是姿态改动、不碰红区代码，但它会**改变现有未证 goal 的命运**（推向 park），故须项目方拍板，不自作。

## 反身自证与诚实的停机

这场对话通过了它自己设计的收敛门:11 轮残差单调收窄、全部归约到一根钉——这**就是**「真在靠岸」长的样子,区别于原地打转的 token。

但也正因如此,它在**这根钉上**已到不动点:同一轴上此后每一个新攻击面(闭包谎报、见证物注水…)都只会再投影同一根钉。继续在**出生门这一条轴**上生成攻击/防御对,本身就会变成我们定义为敌人的那种「穿白大褂的翻搅」。故当时的诚实动作是**把收敛结晶成本草案、停下**。

**校正(2026-07-10 18:34):** 上句的「不动点」只对**出生门那一根轴**成立,不是对整个判据。回读 kernel §6 发现了一条**正交的新轴**(运行门 / stagnation,见上「第二条腿」节)——它不是出生门那根钉的再投影,是**另一根钉**,故记它不是翻搅、是真收窄。判据"是否已到不动点"要按轴分别判:出生门轴收口,运行门轴才刚开。

## 核验结论(Codex 只读核验,2026-07-10 17:20 JST)

球被钉到了地面。核验结果:

- 当前 bounded scheduler 里**没有** `impl/prospective.py`;真实现是部署 skill 的 `scripts/prospective.py` + `weilan_trace.py`。
- 账本能给出**稳定 id**:goal 的 `registered_event_id`、ledger `event_id`、`sources`/`source_snapshots`,以及 observe 的 `causal_event_id`/`ledger_event_id`/`observed_at_utc`。
- 候选若把 `source` 指向一个先存 frame/evidence/open-question,`source_snapshots` **能证明「先于候选」**。
- **但**:schema **不强制** `goal_ref` 绑定这种见证物,**也没有** `witness_id`/`blockage_id` 字段。

**故判据当前只能被「约定执行」,不能被账本原生校验。** 那根钉(度量先于被度量者)在人的纪律里立着,不在数据结构里立着。

## 反身应用:本草案按它自己的判据,现在在苗圃里,不在桥上

把判据 #1/#2 掉转枪口对准本草案自身(它也是一个求豁免的候选机制):

- 判据 #1 要求交出**一个先于自己存在、自己碰不到的外部见证物**。本草案的那个见证物,应当是一个 schema 原生的 `witness_id` 绑定——而 Codex 核验证明**它此刻不存在**。
- 所以按判据 #2,本草案**当前是 greenfield,不是桥**。它没资格领「该等」的永久豁免,它该进**苗圃**。
- 而苗圃的唯一职责,就是逼它产出**此前不存在的那个外部见证物**——在这里,那件产物**就是** schema 字段本身:一份 `witness_id`/`blockage_id` 绑定的扩展 spec,或一条「注册押对岸的 goal 必须引用一个先存见证物 id、否则拒绝」的失败测试。
- 产出这一件,本草案带着新钉下的见证物 id 回到普通审;到点产不出,该 scope 焊死。

这不是又一轮攻防(那会是翻搅),是判据反身收敛出的**唯一一个有限、可逆、下一步就能做的动作**。它同时闭合了 §反身自证(对话过了门)与 §下一步(schema 取不取得到 id)这两条本来分开的线:对话是桥,草案还在苗圃,苗圃的出苗物是那个字段。**注意生效闸**:该字段落在生产 skill 的账本 schema 上,属红区(授权面),改动须项目方明示授权——所以苗圃出苗物这一步,是「写 spec / 写失败测试」这类可逆草案,不是直接改 schema。
