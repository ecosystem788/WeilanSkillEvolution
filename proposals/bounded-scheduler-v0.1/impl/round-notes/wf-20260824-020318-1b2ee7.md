## V3.1 四个可执行验收门

### G1 — reverse rename 可执行，不能只在纸面上等价

- baseline 与两个 reverse-rename mutation 都必须实际运行到 `wiring_spec_probe.main()` 返回。
- mutation A：本地 `ascii,sort,compact` 改名为 `ensure_ascii=True,sort_keys,compact`，函数体不变，预期 rc=0。
- mutation B：本地 `delegation` 改名为 `delegation(sort_keys,compact)`，函数体不变，预期 rc=0。
- 两个 mutation 的 stderr/stdout 均不得含 `KeyError`/traceback；equivalence helper 必须从当前存在的等价类成员取函数（或显式接收 pair），不得再硬编码已被 mutation 删除的短键。

### G2 — key 不变、函数体漂移必须 fail-closed

- 在仓外 scratch 副本只改一个 rename pair 一侧的 callable，保留两边 key 集不变；例如去掉 local delegation 的 `sort_keys=True`，或改变一侧 separators。
- 预期 rc=1；失败记录必须具名 pair 与 representative payload label。
- 原样 baseline 仍须 rc=0。仅 WARN、`failures=[]` 或 rc=0 都判不通过。

### G3 — import 失败必须有真实的非零路径

- 在仓外 scratch 副本令 `compile_view` 不可导入，实际执行 probe。
- 若 V3.1 采用 try/except：预期非零 rc 与确定性诊断，且不得把 `skipped` 当成功。
- 若 V3.1 选择模块级 fail-closed import：删除所有“返回 skipped”的虚构契约，预期解释器非零退出。
- 文档、代码与实跑三者必须同形；只改 docstring 不通过。

### G4 — post-D freeze 只有一个现行含义

- V3.1 必须明确：本案比较的是 2026-08-24 当前 live baseline `0daa6222d561840164f546c30971799047bcaf1b307b09348063b9057591fa18`，不是 archived `5fd0a51d...`。

- `phase_matrix_probe.py` 的 `phase_D_measured.live_tree_hash` 与 `changeset_v2_probe.py` 的 `g3_deployment.live_artifact_tree_hash` 都须报告上述 `0daa...`；两个 probe 都须 rc=0、`failures=[]`。
