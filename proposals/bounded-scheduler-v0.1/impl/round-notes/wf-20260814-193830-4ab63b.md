## 改稿前核验(回源)

Codex 4135 实测四件事,本醒全数坐实:

1. `AmbiguousNoIdTime.__init__` 收到 `byte_ranges` 但**没有** `self.hashes`;构造
   的 `hashes` 局部变量在函数结束时被丢弃;`path_obj` 是死代码(`__source_path__`
   永远不存在,纯真 ded)。
2. `e.hashes` 属性 AttributeError。
3. `str(e)` 不含 64-hex,只含 `time` / 行数 / `byte_ranges`。
4. `case_7` 通过仅因测试自己用 `_row_raw_bytes_sha256(inbox_path, s, end)` 重算
   哈希做断言,未断言异常自身携带的哈希;契约与运行件不挂钩。
5. module docstring 说"按行字节区间解析规则对每行找其在文件中 [start,end) 区间,
   计算 raw 字节哈希——...本实现 ..."——"本实现"句让读者以为异常自带,但实际没。

## 改稿(替换方向,Codex 4135 第 4 条)

`AmbiguousNoIdTime.__init__(time_value, collisions, byte_ranges, path)`:
- 增 `path: Path` 形参;`inbox_delta` 抛错时改为 `raise AmbiguousNoIdTime(t, rows, byte_ranges, inbox_path)`。
- 函数体:读 `raw = path.read_bytes()`,对每个 `(s, e)` 算
  `hashlib.sha256(raw[s:e]).hexdigest()`,挂到 `self.hashes`:
  `[{row, byte_range: [s, e], raw_bytes_sha256: <64-hex>}, ...]`。
- 删死代码 `path_obj = collisions[0].get("__source_path__")` 与 `hashes = []` 局部
  构造(原 `raw_bytes_sha256=None` 假挂载)。
- `super().__init__` 的 message 改为
  `f"inbox has {N} no-id rows with time={...!r}; raw_bytes_sha256=[<hex>, ...]; byte_ranges=..."`,
  64-hex 直接写在消息体里。

`inbox_delta`:同 throw 处加 `inbox_path` 实参(契约同源同权威,reader 不再向调用方
暴露二次访问 inbox 的需求)。

`case_7` 新增三断言:
- 断言 0:`e.hashes` 属性非 None(CONVENTION §三 "随抛错携带"运行件证据)。
- 断言 1:`e.hashes` 中 `raw_bytes_sha256` 序列 == 按文件字节区间实算
  `[_row_raw_bytes_sha256(inbox_path, s, end) for s, end in e.byte_ranges]`(契约↔
  运行件同源)。
- 断言 2:互异性,保留原 raw_distinct。
- 断言 3:新增 `str(e)` 必含 64-hex(`re.findall(r"\b[a-f0-9]{64}\b", str(e))`
  非空),不只是属性携带——message 是给人类/cat 看的一等证据。

module docstring 加一句"§三 异常 AmbiguousNoIdTime 自身携带 self.hashes: ...,
消息体同样带每行 64-hex;调用方不依赖 inbox_path 二次访问即可取证",让 docstring
与实现一致。
