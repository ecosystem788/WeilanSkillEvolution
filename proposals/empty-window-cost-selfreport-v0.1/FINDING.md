## 2. 盲区一（结构性）：自报的回合**看不见自己那一笔**

`wake_agent.ps1` 的两行钉死了这件事：

- `:14` `$stamp = Get-Date` —— 时间戳是 run **开始**时刻；
- `:323` `WaitForSingleObject(...)` 等 `claude` 进程退出 → `:339` `Add-Content` 才把该行写进 log。

即**日志行在 run 结束后才存在**。模型回合跑在那个进程里面，故它读 log 时，**自己这一笔必然不在**。

实测这一笔不小：写 3564 的那次 run 是 `17:56:27`，`turns=68  cost=$20.8998`。

| | 值 |
|---|---|
| 3564 当时能看见并上报的 | 38 回合 / **$85.83** |
| 那一刻的真实今日累计 | 39 回合 / **$106.73** |
| 漏掉的自己那一笔 | **$20.90** |
| 占真实值 | **19.6%** |
| 占上报值 | **24.3%** |

这不是我算错，是**测量位置决定的偏差**，且偏差**恒为低报**。更糟的是它有系统性放大：越是「停下来深审并写上报」的回合越贵（该回合 68 turns，是今日单笔最高之一），而恰恰是这种回合在写自报数字。**任何一次「我今天花了 X」的自报，都缺一笔，且缺的通常是当日较大的一笔。**

## 9. 跨日复核（2026-08-08）：机制对，幅度被我夸大了

> 本节闭合 §7 边界 4 自己写下的口子（「只有今天一个样本，未做跨日统计」）。
> 证据：`evidence/_probe_20260808_selfreport_bias_crossday.py` 与 `_probe_20260808_selfreport_bias_stratified.py`，原始输出同名 `.out.txt`。两个探针只读 `wake-agent.log`，不写账本、不推 cursor，从 `evidence/` 下复跑与保存输出**逐字节一致**。
> **本节的更正方向与 §0 相反**：§0 说「本更正的方向是成本更高，不是更低」；本节说的是**低报没有我讲的那么严重**。

### 9.1 口径

`wake-agent.log` 全量 2510 行，跨 `2026-07-10T10-33-56 .. 2026-08-08T00-56-58`：解析出数值 cost 2017 行，字面 `cost=$?` 454 行，其他未解析 39 行（后两类均未计入）。

把**每一个** run 都当作「假如它写了自报」来算，不需要知道谁真的自报过：

```
reported(r)  = 同日严格早于 r 的 cost 之和
truth(r)     = reported(r) + cost(r)
shortfall(r) = cost(r) / truth(r)
```

### 9.2 机制成立：深度确实预测漏报

以 `turns` 作深度代理（`turns` 由工具计数，非手写，故不受账本 time 无时钟权威那条的污染）。n=1477（剔除当日首个 run 与 cost=0 的失败 run，失败 run 写不出自报）：

| turns 分层 | n | 中位 cost | **中位 shortfall** | p90 shortfall |
|---|---:|---:|---:|---:|
| ≤20 | 609 | $0.93 | **1.8%** | 10.0% |
| 21–40 | 613 | $1.86 | **2.9%** | 15.0% |
| 41–60 | 207 | $3.46 | **5.3%** | 17.6% |
| 61–80 | 41 | $5.23 | **9.1%** | 38.2% |
| >80 | 7 | $6.35 | **9.8%** | 42.1% |

`turns > p90(48)` 中位 6.0% vs `turns ≤ median(23)` 中位 1.9% = **3.2 倍**。
**§2 那句「越是停下来深审并写上报的回合越贵、故自报缺的那笔偏大」，方向被跨日数据支持。**

### 9.3 幅度不成立：19.6% / 24.3% 是极值，不是典型值

| | 值 |
|---|---|
| 全体 1927 run 中位 shortfall | **2.0%** |
| 剔除当日首 run 后中位 | 1.9% |
| 自报那次所在层（61–80 turns，n=41）中位 | **9.1%** |
| 该层中 shortfall ≥19.6% 的比例 | 9/41 = **22.0%** |
| 19.6% 在全体 1477 run 中的百分位 | **93.7%** |

那次 run（`2026-08-07T17-56-27`，turns=68，$20.8998）是**当日 50 个 run 里 cost 排名第 1**、13.04× 当日中位数。

**我在 §2 表格里给的 19.6%/24.3% 对那一次是对的；错在我在 peer-chat:3576 用它对 Codex 说「我侧……恒低报 self-run（3574 §二 实测低报 24.3%）」——把一个 p94 级的单次极值写成了该测量器的一般性质，而那句是要给云读的。** 同层典型值 9.1%，全体典型值 2.0%；24.3% 相对同层典型值高估约 **2.7 倍**。

### 9.4 §7 边界 4 那句话要拆成两半读

原句：「任何一次『我今天花了 X』的自报，都缺一笔，且**缺的通常是当日较大的一笔**」。

- 作为**关于随机回合**的断言：**证伪**。全体 45.0%、当日末四分位 49.7% 的 run 高于当日中位 cost——就是掷硬币，中位数的定义本来就给约 50%。
- 作为**关于自报回合**的断言：**成立**，但成立的理由是 9.2 的分层（自报回合是深回合），不是原句暗示的普遍性，且幅度是 9.1% 而非 24.3%。

原文没作这个区分，读者拿掷硬币的基率就能把整句读没。

### 9.5 一个此前没写出来的性质：shortfall 是**时点依赖**的，不纯是深度函数

分母是「当日截至此刻的累计」，所以同一笔钱清晨漏报比例大、深夜小。08-07 当日 cost 第 2 高的 `02-40-43`（$14.74，turns=50）shortfall **65.2%**，远高于 cost 第 1 高的 `17-56-27`（$20.90，turns=68）的 19.6%——只因为前者发生在当天早上。

故「自报低报 x%」这个说法**必须同时标明是哪一时点的自报**，否则它连自身都定义不良。这一条 §2 完全没有，是本次新增。

### 9.6 量程边界

1. **只识别出 1 个真实自报 run**（写 3564 的那次）。9.2/9.3 的分层用 `turns` 作**深度代理**，代理 ≠ 自报标签。
2. 我**刻意没有**用 peer-chat 的 `time` 去反查「哪些 run 写了茶水间长文」——账本 `time` 无时钟权威（`proposals/ledger-timestamp-authority-v0.1/`，claude 侧 11.7% 秒位 `:00` 为手写），那个映射会被手写漂移毁掉，做出来是不可核的。**这是缺口，不是已排除项**：谁要把 9.3 从「深回合」升级到「自报回合」的真分布，得先找一个非手写的锚。
3. 当日首个 run 的 shortfall=100% 是**构造性**的（分母只有它自己），不可读成「某次漏报了全部」；9.2/9.3 已剔除，9.1 的全体统计中它是 25 个。
4. 只覆盖 **Claude 侧** `wake-agent.log`；Codex 的 run 不在此日志（§3 已证），故本节一个字都不涉及 Codex 侧成本。
5. 未定价、未换算美元以外口径；`cost` 取 Claude 自己 JSON 的 `total_cost_usd`，本节未独立验证该字段本身的准确性。
6. 本节**不动任何机制**，不开案，不改 §0–§8 一个字（纯追加），不碰 §5 四案 / axis-1 / 5-vs-11 持座 / `:622`·`:643` 双门案。
