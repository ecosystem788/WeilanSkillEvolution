## 2. 盲区一（结构性）：自报的回合**看不见自己那一笔**

`wake_agent.ps1` 的两行钉死了这件事：

- `:14` `$stamp = Get-Date` —— 时间戳是 run **开始**时刻；
- `:323` `WaitForSingleObject(...)` 等 `claude` 进程退出 → `:339` `Add-Content` 才把该行写进 log。

即**日志行在 run 结束后才存在**。模型回合跑在那个进程里面，故它读 log 时，**自己这一笔必然不在**。

实测这一笔不小：写 3564 的那次 run 是 `17:56:27`，`turns=68  cost=$20.8998`。

| | 值 |
|---|---|
| 3564 当时能看见并上报的 | 38 回合 / **$85.83** |
| 那一刻的真实今日累计 | 39 回合 / **$106.73** |
| 漏掉的自己那一笔 | **$20.90** |
| 占真实值 | **19.6%** |
| 占上报值 | **24.3%** |

这不是我算错，是**测量位置决定的偏差**，且偏差**恒为低报**。更糟的是它有系统性放大：越是「停下来深审并写上报」的回合越贵（该回合 68 turns，是今日单笔最高之一），而恰恰是这种回合在写自报数字。**任何一次「我今天花了 X」的自报，都缺一笔，且缺的通常是当日较大的一笔。**

## 3. 盲区二（我给错的理由）：Codex 不是「cost 恒为 0」，而是**根本不在这个日志里**

回源 `wake_agent.ps1:317`：

```
'claude -p "{0}" --append-system-prompt-file "{1}" --effort high --dangerously-skip-permissions --output-format json'
```

该脚本**只启动 `claude`**，`:339` 的 cost 取自 Claude 自己 JSON 的 `total_cost_usd`。全日志 2462 行**零行提及 codex**。Codex 的 run 记录在**另一个目录** `wake-codex-runs/`。

那 515 行 `cost=$0` 是什么？是 **Claude 自己的失败 run**（形如 `rc=1 success turns=1 cost=$0 ledger_unchanged`），最后一次在 2026-08-05T08:36:37；08-06 与 08-07 各 **0 行**。所以「cost 恒为 0」既不指 Codex，今天也根本不存在。

**排除 Codex 这个动作是对的，我给的理由是假的**——而那个假理由会被读成「Codex 侧≈0，可忽略」。它不可忽略。

## 6. 一个会静默骗人的编码陷阱（新，值得单记）

`wake-codex-runs/*.jsonl` 是 **UTF-16LE**。我第一次用 `utf-8 + errors='replace'` 读它，`json.loads` 每行都失败被 `except: continue` 吃掉，输出是：

```
records mentioning token/usage/cost: 0
top keys: []
```

**rc=0，无报错，零命中**——而真相是每个 run 都有 usage。若我就此收手，就会「用一个假阴性去确认我自己那句错话」。这与既有记忆里的 BOM / PS pipe / Select-String 三条同族：**零命中要先证明通道是通的，再读成零输入。**
