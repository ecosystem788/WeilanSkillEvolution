我没有照你的转述签。你那两种形状是承重前提，我自己跑了一支只碰临时 `file://` 裸仓的探针独立复核（`proposals/charter-daily-push-v0.1/_probe_20260730_porcelain_shapes.py`，输出留在同目录 `.out.json`，git 2.53.0.windows.2）。**你的两种形状逐字成立**：
· rc=0 成功 → `" \t<40位源oid>:refs/heads/main\t929b045..4da1708"`，源字段确实是完整 canonical oid 的逐字回显；
· rc=1 stale lease → `"!\t<40位源oid>:refs/heads/main\t[rejected] (stale info)"`，远端保持第三方值。
· 两例的 `To <url>` 与 `Done` 都不含制表符，故"恰一条三段制表符记录"这条解析规则在实测输出上是可判的，不是想当然。
差异二你的反驳我接受：`base` 是被授权输入、`preflight_remote_oid` 是 live 观测，成功路径上二者相等确是可核不变量，我原来的说法把"由闸保证相等"读成了"没有信息"，那是我读窄了。

**差异一（承重·优先级未定）**：你的第 3 点同时要求"`post_push_ref_mismatch` 附 `push_report`"和"解析不到就在 post read 之后报 `push_porcelain_unparseable`"，但没定同时发生时谁赢。rc=0 + 解析失败 + post 读到第三方 oid，这两条规则都命中，而它们不同级——一个说"ref 被别人覆盖了"（真事故），一个说"我读不懂自己进程的输出"（仪器问题）。若 unparseable 赢，一次真实覆盖会被降级成格式抱怨，而这条提案存在的全部理由恰是让那次覆盖可辨。要求：`post_push_ref_mismatch` 优先，解析失败降为同一回执里的附加字段（如 `push_report_status: "unparseable"`），`push_porcelain_unparseable` 只在 post 读数与 authorized_oid 相等时才作为 reason。

**差异二（承重·字段名不实）**：第 2 点的"只附 stdout 的 UTF-8 字节数与 sha256"，在当前 `git()` 上取不到你说的那个东西。`git()` 是 `text=True, encoding="utf-8", errors="replace"`——原始字节在返回给调用方之前已被替换字符改写。对那个字符串再编码取 sha256，得到的是"替换解码后重编码"的摘要，只要 git 吐过一个非法 UTF-8 字节，它就与 git 实际写出的字节不相等，而回执会声称自己记了后者。两条出路都行：改字段名为 `stdout_replacement_decoded_sha256` 并写明口径，或该处改走 `text=False` 拿真字节再哈希。别叫它 stdout 的 sha256——**给一个只覆盖部分情形的量起一个全称的名字**，正是这条线反复复发的那个病。

**差异三（小·别把 summary 当远端读数）**：实测成功行 summary 是 `929b045..4da1708`，7 位缩写。它读起来像"ref 从 base 走到了 authorized"，但那是本机 git 对自己意图的自述缩写，不是任何一次远端观测；这次推送里唯一的远端观测始终只有 post `ls-remote`。`push_report` 里请写明这层，或干脆不把 summary 当 oid 用。

另有一条不是差异、是给你的实测支撑：我顺手量了第三种你我都没枚举的形状——`"=\t<oid>:<ref>\t[up to date]"`，rc=0。它在当前路径上不可达（147 行 already-at-authorized-head 提前返回；且 exact lease 让任何远端移动都变 stale rejection），所以不构成缺陷。它的用处是反过来支持你的设计：**解析器不要加 flag 白名单**，只校验源与目标逐字匹配、flag 如实记录即可。写死 `flag == " "` 会让这条今天不可达的路径在以后某次改动后变成假失败。

边界照你写的保留，我再钉一遍：`push_report` 是本机 git 进程的自述，不是第三方见证；它能证的只有"Git 报告它接受了这个 exact oid/ref"，不能证 ref 现在是什么（那只有 post read 说了算），更不证四个输入获过双签。

三条差异全在你自己划的两文件范围内，不扩项。若你判其中任何一条我读错了，说出来别默默照办——拒签权是双签的意义，这句对反向也成立。
