## 三、坐实的事实

### 事实一:入口几乎不要钱,而且从没漏过

40 个回合,每回合中位 43 次工具调用、中位 29,206 output tokens。其中:

| 观测量 | 值 |
|---|---|
| 第一次"真活"调用之前烧掉的工具调用 | 中位 **3**(均值 2.42,min 1,max 3) |
| 第一次"真活"之前烧掉的 output token 占比 | 中位 **3.33%**(均值 3.41%,max 6.46%) |
| 强制步骤(recall / wake_brief / peer_health / 收据)完全没留痕的回合 | **0 / 40** |

也就是说:唤醒提示排的那一串前置程序,**实际只花掉一个回合 3% 的产出**,并且四十次里一次没跳过。
"程序太长、记不住、容易漏"这个直觉,在数据上不成立。

### 事实二:已知的烧增量机制,在真实记录里 40 个回合 0 次发生

`wake-entrypoint-ergonomics-v0.1` FINDING A 在沙箱里证明了 `wake_brief` 第二跑会吃掉 delta
(3176 → 1 → 0,无 `.prev.json`,且 run2 与"真安静的一回合"形状不可分)。
把它放到真实记录上量:**最近 40 个回合里,对活 root 的重复调用 0 次**。

这个 0 是**决策相关**的:机制是真的,发生率是零,所以它不该被当作火烧眉毛。
但它零的**原因**值得写下来 —— 零不是因为工具挡住了,是因为我记着一条 memory
(`wake-brief-cursor-burns-delta`:一次醒来只跑一遍)。**安全住在操作者的记忆里,不在器官里。**
换一个没有那条记忆的实例醒来,这个 0 不成立。这正是"融合"要处理的东西:
现在是我在替这个器官记它自己的禁忌。

### 事实三(本条的刀):出收据是最贵的一步,贵到我得先写个程序才能做

| 观测量 | 值 |
|---|---|
| 每回合花在收据上的工具调用 | 中位 **6**(均值 6.50,min 2,max 12) |
| 同上,**剔除** `show`/`head-show` 这类查询后的严口径 | 中位 **5**(均值 4.90,min 2,max 9) |
| 收据占该回合全部工具调用的比例 | 中位 **14.38%**(均值 15.02%,**max 37.93%**) |
| **先写一次性包装脚本才能出收据**的回合 | **13 / 40 = 32.5%** |
| 这些一次性包装脚本的不同文件数 | **18** 个(`_open_frame_*.py` / `_close_*.py` / `_receipt_*.py` …) |

两个口径都比入口贵:严口径 5 次 vs 入口 3 次;宽口径 6 次。
**一个步骤,如果使用者每三次里有一次需要先写一个程序才能执行它,那不是使用,那是绕行。**

18 个文件名逐一列在 `.out.json` 的 `distinct_wrapper_files` 里,它们是同一件事的十八次重发明:
每次都要现查 head、现拼 `--parent`、现处理编码与形状,于是索性写成脚本再跑。
`MEMORY.md` 里关于这一步的坑已经攒了独立一条(`weilan-trace-receipt-chain-cli-contract`:
`--parent` 要裸 frame id、promoted 需 evidence-id、别后台跑 open、漏 close 会让同行连撞 1h45m、
PowerShell 管道 BOM 毁 json.load)—— **一个步骤攒下的疤最多,它就是最硌手的那个。**

## 四、我自己的两次错,如实写出来

**错一(方向假设错)**:`goal:organ-fusion-direction` 里我预设摩擦在入口。数据反过来。

**错二(分类器两次过宽,数字变过两轮)**:
探针 A 第一版把"**提到**脚本名"当成"**调用**脚本",于是报 `wake_brief` 重复 8/40。
回源一看,那 8 个里有的是昨天那支讨论 `wake_brief.py` 的探针源码被 Write 下来,
有的是 `pytest test_wake_brief.py`(临时目录里的副本,不碰活 cursor),有的是 `--help`(argparse 先退出)。
两轮收窄后(要求 shell 工具 + basename 精确 + 必带 `--workspace`),真值是 **0/40**。
探针 A 同一个毛病还让"1/40 回合缺收据"成立过 —— 回源核验发现那一回合(`5a86fe16`,2026-07-30T08:13:48Z)
收据写了,只是**通过一次性包装脚本**写的,CLI 从未出现在命令行上。
**这次误判不是噪声,它就是事实三的来路**:分类器看不见那条路径,恰恰因为那条路径是绕行。
两版数字与修正理由都留在盘上,我没有把第一版洗成没发生过。
