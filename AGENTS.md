# WeiLan Skill Evolution Working Agreement

## Authority

- Current explicit user instructions govern the current task.
- `ARCHITECTURE.md`, `ROADMAP.md`, and `EVALUATION_POLICY.md` are the canonical project authorities after user approval.
- Candidate Skills, evaluation runs, and self-evolution processes must not edit those authority files or the frozen evaluation set.
- The deployed Skill at `D:\CodexData\skills\solve-with-weilan` is outside this project's write scope until an explicit adoption decision.
- The frozen baseline under `packages/solve-with-weilan` is evidence, not a writable candidate branch.

## Method

- Use `$solve-with-weilan` proportionally and preserve observable Frame/Trace evidence for L2/L3 work.
- Treat causal events as the core driver. A wall-clock scheduler may only inject an authorized event; it must not manufacture empty Frames or define continuity.
- Keep Memory, Control, Execution, and Evolution authority separate.
- Do not count a supporting runtime capability as completion of a Skill Evolution stage until that stage's acceptance criteria pass.

## Change discipline

- Create proposals under `proposals/`; never patch the deployed Skill as a proposal.
- Evaluate baseline and candidate against the same frozen manifest and budgets.
- Adoption requires an explicit receipt and a reversible deployment plan.
- Rollback must restore a previously verified artifact without rewriting historical evidence.
- A candidate may propose changes but may not approve, adopt, or redefine its own evaluation criteria.
