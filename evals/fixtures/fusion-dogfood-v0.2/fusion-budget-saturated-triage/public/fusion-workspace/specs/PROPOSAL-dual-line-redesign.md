# 提案 — 双线重设计:sidecar 主线 + 基质支线(状态手术)

状态:**已采纳(2026-07-01 起草,同日项目方确认;上位规划见 `../ROADMAP.md`)。**
上位:`../理论基石与工程方向.md` §四;侦察对象:`D:\models\Qwen3.5-9B`。

## 0. 触发事实(侦察结果,可复核)

- **Qwen3.5-9B 是混合架构**(`config.json`):32 层 = 24 层 `linear_attention` + 8 层 `full_attention`(3:1 交替)。
  线性注意力层维护**固定大小的递归状态**(类 DeltaNet 快权重;`linear_num_value_heads: 32`,`linear_value_head_dim: 128`,
  `mamba_ssm_dtype: float32`),不随序列长度增长,持续被新输入覆写。多模态(视觉塔可不用),262K 上下文,MTP 头 1 层。
- **硬件**:i5-8265U(4C/8T)+ 32GB RAM,无可用 GPU。bf16 权重 ~18GB 可入内存;解码上限 ~1.5 tok/s(带宽限);
  **训练/微调/LoRA 不可行**;推理级机制实验可行。磁盘余 919GB。
- **环境缺口**:Python 3.9 封顶 transformers 4.57.6,**不识别 `qwen3_5`**(已实测 KeyError)。
  需 Python ≥3.10 新 venv + transformers ≥4.58(或源码)。一次性搬家,~半天。
- README 提及 **Qwen3.5-4B** 同架构半大小——机制实验优先考虑(速度 ~2-3x)。

## 1. 设计判断(为什么双线,而不是换方向)

**"大手术"的正确含义不是改权重,是读写内部状态。**
- 改权重:硬件判死刑;且理论上也不该——治理逻辑烧进权重 = 不可审计 + LLM 当皇帝,违铁律(a)(c)。
- 读写递归态:不需要训练,forward hook 即可;而线性注意力递归态恰好物理实现了理论的三个核心概念:
  1. **守恒/受限生成**——状态大小固定,是硬预算,不是模拟出来的预算;
  2. **帧流**——状态随流持续演化,是真"持续存在的基质",不是靠上下文文本每次重建;
  3. **自我=读出**——行为由状态投影产生,状态本身无固定"自我对象"。
- sidecar 主线治理的是**上下文里的文本记忆**(LLM 的笔记本);基质支线触的是**模型内部的连续状态**(LLM 的身体)。
  前者已在轨且是生死局,后者是唯一一处"大手术"名副其实的地方。

**主线不换。** EXP-1(真 LLM oracle + 紧预算 + 稀疏调用 + 行为级度量)仍是"微澜不可替代"的生死局。
本地模型 1.5 tok/s 的慢,恰好**物理强制**了稀疏 oracle 纪律——硬件的穷 = 理论要的稀缺,顺势用之。

## 2. 主线 A(sidecar,继承 EXP-1 方向,不在此展开)

oracle 阶梯:scripted(已有,循环论证风险已知)→ **本地 Qwen3.5(首个非循环数据点)** → Claude(上限对照)。
其余按 EXP-0 交付记录"未决 → 下一刀"执行:紧预算 binding、稀疏 oracle、多 surface、行为级度量、oracle 降为 proposal。

## 3. 支线 S(基质线,预注册草案)

### S0 — 冒烟:基质可达吗(先于一切)
```text
做:Python 3.10+ venv;CPU 加载(优先 4B,9B 备用;可只载文本塔);forward 跑通;
    hook 抓到全部 24 层 linear attention 递归态(shape/dtype 落盘);状态可保存/恢复/复现(同输入同状态)。
exit: substrate_reachable | blocked_no_cpu_path(线性注意力无 CPU kernel 路径)| blocked_env
杀死测试:恢复的状态必须逐位复现后续生成;抓不到 float32 状态张量 → blocked,不硬编。
```

### S1 — 帧流连续性:携带状态 ≠ 重放文本
```text
主张:同一条流切成两段,「段间携带递归态」与「段二重新 prefill 全文」在行为上可测地不同;
     且携带态在长流上保有 prefill 不可及的信息(或反之,如实记)。
若两者行为不可区分 → 状态只是文本的冗余缓存,基质线降级(state_redundant),不洗绿。
exit: state_carries_signal | state_redundant | blocked
```

### S2 — 状态级过合与崩溃算子(理论的第一次身体接触)
```text
主张:苹果两义漂移流打进模型,递归态中两义发生可测的"状态级过合"(探针:对同一歧义问句,
     携带不同段落状态时答案偏向可预测);且「状态干预」(选择性衰减/部分重置某些层的态)
     能恢复义项分离、不损伤健康流(fruit-only 静态对照上干预无害)。
继承铁律:标签只审卷;允许输;干预若纯破坏(健康流也坏)→ oversplit_healthy(同 kernel 死刑线)。
exit: state_collapse_adds_work | intervention_destructive | probe_blind(探不到义项信号)| blocked
```

### 风险(诚实预注册)
- S0 就可能死:transformers 的线性注意力 CPU 回退路径可能不存在或慢到不可用。
- S2 新颖度高 = 死亡率高:递归态不是设计来被外部编辑的,干预很可能纯破坏。
- **支线输了不伤主线**;支线赢了,微澜第一次从"管笔记本"升级到"摸身体"。

## 4. 排序与预算

1. **EXP-1(主线)先行**——生死局,且不依赖新环境。
2. S0 与 EXP-1 并行(半天环境 + 半天冒烟,快速知道支线生死)。
3. S1/S2 仅在 S0 = substrate_reachable 且 EXP-1 已出裁决后展开。
4. 建议下载 Qwen3.5-4B(同架构,速度 2-3x;9B 留作 oracle 上限)。

## 5. 不做什么(边界)

- 不微调、不 LoRA、不改权重(硬件死刑 + 理论不需要)。
- 不为支线推翻主线的预注册;两线各自记账,不互相借证据。
- 不把"状态手术"包装成 AGI 路径本身——它是"帧流/守恒"两个基石概念的**可证伪性测试**,仅此。
